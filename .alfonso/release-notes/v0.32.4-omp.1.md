# v0.32.4-omp.1

OMP compatibility release rebased directly onto official Magic Context v0.32.4.

## Upstream updates

This build includes the official v0.32.2 and v0.32.3 cache-boundary resilience fixes and v0.32.4's Pi dreamer retry prompt-integrity fix. Zero-tool dreamer children now fail before spawn when their required system prompt is missing.

## OMP compatibility retained

- Every OMP child prompt is delivered byte-exactly through `@user-prompt.txt`.
- Pi-only `--no-prompt-templates` and `--no-context-files` flags remain omitted only for OMP.
- OMP child allowlists translate `find` and `ls` to `glob` and omit unavailable `aft_*` tools.
- Disabled `ctx_memory` and `ctx_note` tools remain absent from OMP's registered and model-visible tool surface.
- The explicit `setup --harness omp` workflow and single plain `mc:` status surface remain isolated from native Pi and OpenCode behavior.

## Verification

The rebased fork passed 676 Pi tests, 275 CLI tests with 2 skipped, and 2,985 shared-plugin tests. Pi, CLI, and shared-plugin typechecks passed, production bundles rebuilt, and fork-modified Pi/CLI packages passed lint.

The model-visible context-tool inventory was exactly `["ctx_expand","ctx_reduce","ctx_search"]`. A real `/ctx-recomp` primary historian run rebuilt three compartments in one pass over raw messages 1–6, and `/ctx-status` reported three compartments, zero memories, zero notes, and `Historian: idle`.
