# v0.33.0-omp.1

OMP compatibility release rebased directly onto official Magic Context v0.33.0.

## Upstream v0.33.0

- **Memory Mural** adds opt-in visual memory injection: compressed memory cues can be packed into a deterministic PNG rather than consuming the equivalent text-token budget.
- **Faster Pi startup** defers the embedded QuickJS sandbox, substantially reducing cold import time for the extension and its historian/dreamer children.
- **Compaction reliability and performance** improve through pressure-gated tool reclaim, cached warm-pass tag/trigger work, and guarded cue-compression time slicing.
- Schema migrations v54–v68 are included. Every Magic Context binary sharing a database must upgrade together.

## OMP compatibility retained

- OMP child prompts continue to use the OMP-compatible prompt transport, while Pi-only prompt-template and context-file flags remain excluded from OMP children.
- OMP child-tool allowlists still translate unavailable tools and keep disabled context tools out of both registered and model-visible surfaces.
- `setup --harness omp`, the single `mc:` status surface, and OMP extension controls remain isolated from native Pi and OpenCode behavior.
- `omp.subagents.compaction` remains an opt-in setting. When enabled, lifecycle-attested OMP task subagents compact their own transcripts using the configured historian, fallback chain, thresholds, protected-tail policy, and history budget. Magic Context's own internal children remain excluded.

## Verification

The rebased fork passed workspace lint, TypeScript checks, production builds, and the complete workspace test suites: 3,249 shared-plugin tests, 726 Pi/OMP-plugin tests, and 284 CLI tests with 2 intentional skips. The targeted OMP subagent-compaction lifecycle suite passed 2/2 tests.
