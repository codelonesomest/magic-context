# v0.32.4-omp.2

OMP compatibility release adding opt-in Magic Context compaction for OMP-managed task subagents.

## OMP task-subagent compaction

- Adds `omp.subagents.compaction`, defaulting to `false` for a conservative rollout.
- When enabled, OMP lifecycle-attested task children compact their own transcripts using the existing historian model, fallback chain, thresholds, protected-tail policy, and history budget.
- Task identity comes from OMP's persisted child-session header delivered through `task:subagent:lifecycle`; filename heuristics are not used.
- Magic Context's own historian, dreamer, sidekick, and migration children remain excluded by the existing `MAGIC_CONTEXT_PI_SUBAGENT` guard.
- Task-child status and system-prompt guidance reflect that compaction is active; native Pi and OpenCode behavior remain unchanged.

## Correctness hardening

- Carries the scheduler's protected-tail boundary snapshot into the detached historian, preventing a triggered task historian from becoming a missing-boundary no-op.
- Treats lifecycle-attested task sessions as subagents throughout transform and compartment injection so automatic scheduling is deliberate and observable.
- Documents the host boundary: normal OMP task sessions, nested tasks, isolated tasks, and in-process parked/revived tasks are supported. OMP cold revival after a full host restart does not currently reload preloaded extensions upstream, so Magic Context cannot attach in that special path.

## Verification

The release candidate passed 682 Pi-plugin tests with zero failures in a hermetic configuration, all workspace TypeScript checks, and production builds for the shared plugin, Pi/OMP plugin, and CLI.

A persistent isolated OMP task transcript was classified with `is_subagent=1`, triggered its own `pq/gpt-5.5` historian through the OMP-compatible prompt transport, published one compartment covering messages 1–3, queued one raw-history drop, applied that deferred operation on the next task turn, and drained the Pi compaction marker with `tokensBefore=296`. The isolated database ended with `compartment_in_progress=0`, no pending Pi marker, a successful historian run producing one compartment, and the compacted session-history cache materialized.
