# v0.32.1-omp.1

This is the maintained Oh My Pi compatibility build of official Magic Context v0.32.1. It contains the complete upstream hardening release and reapplies the fork's OMP integration without changing native Pi or OpenCode behavior.

## Upstream v0.32.1 hardening

- Emergency overflow fails closed only when a provider-proven context limit is at least 95% consumed and no fold materializes; estimator drift alone cannot abort a healthy turn.
- Historian output with narrative-bearing compartment gaps is rejected instead of silently absorbing unseen history. Tool-only gaps may still heal.
- Historian summaries use first-person voice, and compartment titles are sanitized in TypeScript and Rust renderers.
- Pi image-only tool results retain an `[image stripped]` placeholder for Anthropic, and residual display-only status leakage on older Pi versions is closed.
- Storage migrations v51/v52 harden concurrent startup and persist provider-proven overflow state.
- Notification, TUI/RPC, smart-note sandbox, maintenance, and CLI config/doctor paths receive the official v0.32.1 lifecycle and safety fixes.

See the [official v0.32.1 release notes](https://github.com/cortexkit/magic-context/releases/tag/v0.32.1) for the complete upstream changelog.

## OMP compatibility retained

- First-class `setup --harness omp` flow with linked local-plugin installation and OMP model discovery.
- Active-host child invocation, so OMP does not require a separate `pi` executable.
- OMP omits Pi-only child context flags and delivers child prompts through byte-exact `@file` arguments.
- OMP 17 strict tool allowlists translate `find`/`ls` to `glob` and omit unavailable `aft_*` tools; native Pi retains the upstream-compatible tool list.
- Memory-disabled OMP sessions omit `ctx_memory`; `omp.tools.ctx_note: false` omits `ctx_note` and corresponding prompt guidance.

## Upgrade notes

This release advances the fork from `v0.32.0-omp.4` to official upstream `v0.32.1`. It includes database migrations v51 and v52, so use the matching CLI/plugin build and do not downgrade an upgraded shared database with an older CLI.

The development installation links OMP directly to `packages/pi-plugin`; rebuild the package after checkout. Do not replace the linked fork with the official Pi package via `omp plugin upgrade`.
